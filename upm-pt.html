04 · ARCHITECTURE

왜 3-Tier인가: 장비마다 한 가지 역할만 맡긴다

UPM은 PC 하나로 끝나는 프로그램이 아니라, 정보를 만드는 PC · 모아서 판단하는 서버 · 보여 주고 명령을 받는 기기가 서로 다른 장비로 이루어진 인프라 그 자체다.

TIER 1 · 수집·실행
PC 클라이언트
C# WPF · .NET 8
  • 1초마다 자원·프로세스 수집
  • 게이지 표시
  • 서버 판정을 재검증 후 종료
TIER 2 · 처리·저장
라즈베리파이 서버
FastAPI · MySQL
  • 데이터 저장 (MySQL)
  • 종료 대상(killList) 판정
  • 24시간 저전력 상시 가동
TIER 3 · 표현·제어
보고 제어하는 기기
Flutter · Web · Ulanzi
모바일 앱관리자 웹스트림덱형 컨트롤러
  • 실시간 상태 확인
  • 원격 최적화·종료 요청
통신 HTTP REST API(JSON) · 외부망 접속 ngrok HTTPS 터널 · 컨트롤러 키 화면에 지표 실시간 표시
05 · WHY IT WORKS

3-Tier로 나눠서 얻은 네 가지

역할 분리

확장성

서버 API만 맞추면 PC 프로그램을 고치지 않고 새 기기를 붙인다

서버 API모바일웹컨트롤러+ 새 기기

안정성

보안·상시성
